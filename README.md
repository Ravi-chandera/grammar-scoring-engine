# Grammar Scoring Engine

An end-to-end multimodal system that predicts a continuous grammar score from a spoken response. This repository is my solution to the SHL Hiring Assessment 2026 Kaggle challenge.

The final model combines information that survives transcription with information that does not:

- **WavLM** represents pronunciation, pauses, repairs, rhythm, and other acoustic cues.
- **Whisper + TF-IDF** captures local word, character, and grammatical patterns.
- **MPNet** adds a frozen contextual representation of the transcript.
- **DeBERTa** adds a supervised transcript regressor whose errors complement the simpler models.

The final 5-fold out-of-fold result on the rubric-valid training set is:

| Metric | Score |
|---|---:|
| RMSE | **0.532446** |
| Pearson correlation | **0.851207** |

These are local OOF metrics, not a claimed leaderboard score. The Kaggle score was not present in the exported artifacts, so I have deliberately not invented one.

## Why I approached it this way

The task looks like an audio-regression problem, but the target is specifically **grammar**, not general speaking quality. My first assumption was therefore that a strong solution should understand the words and sentence structure. At the same time, automatic transcription can silently correct, omit, or hallucinate speech, so a transcript-only model would leave useful information behind.

I built the solution incrementally. Every additional component had to improve held-out predictions and contribute errors that were not already captured by the current ensemble. This kept the final architecture explainable despite using several representations.

## Data audit: two important findings

The provided data contains 769 training recordings and 216 test recordings. All 985 files are mono, 16 kHz WAV files, mostly 45–60 seconds long.

Before modeling, I found two inconsistencies that changed the implementation:

1. **Thirty-seven training labels are `0`, outside the published 1–5 grammar rubric.** They all come from a separate filename range and have substantially lower Whisper confidence than the other training examples. A simple acoustic model could identify this batch almost perfectly, which is a warning that it was learning a source/audio-quality regime rather than grammar. The test set contained almost no comparable examples. I therefore trained the grammar regressor on the 732 positive-label rows and clipped final predictions to the rubric range `[1, 5]`.
2. **`sample_submission.csv` is inconsistent with the evaluation data.** It has 204 rows, while `test.csv` and the physical test directory agree on 216 files. The final file is built in validated `test.csv` order and checked against the test directory.

Train and test also reuse 212 basenames for different recordings. Every transcription cache is consequently keyed by both `split` and `filename`; joining on filename alone would mix train and test audio.

## Experiment journey

### 1. Handcrafted acoustic baseline

I began with duration, RMS energy, silence ratios, pause counts, zero-crossing rate, and spectral statistics. Ridge and ExtraTrees established that the audio contained predictive signal, but most of the apparent strength came from separating the anomalous zero-score batch. After removing those rows, performance dropped to RMSE 0.84826 / Pearson 0.55186.

This was a useful baseline and data diagnostic, but not a satisfactory grammar model.

### 2. Whisper transcription and sparse text features

I transcribed every recording with `faster-whisper` using `medium.en`, beam search, VAD, and word timestamps. The transcription stage is checkpointed every 25 files so a long Kaggle run can resume safely.

The first serious grammar model used:

- word TF-IDF unigrams and bigrams;
- character TF-IDF 3–5 grams;
- ASR confidence and timing statistics;
- speaking-rate and speech-span features;
- interpretable linguistic features such as lexical diversity, filler ratio, conjunction/subordinator use, repetition, and words per sentence.

Vectorizers, scalers, and regressors are fitted independently inside each fold. This model reached RMSE 0.68057 and Pearson 0.74179.

### 3. Frozen MPNet embeddings

I encoded each transcript with `sentence-transformers/all-mpnet-base-v2` and trained small Ridge/SVR regressors on the frozen embeddings. The best model was an RBF-SVR using MPNet plus the numeric ASR/linguistic features.

MPNet alone improved the sparse baseline, and a 60% MPNet / 40% TF-IDF blend reached RMSE 0.64538 and Pearson 0.77175. The blend helped because the two representations made different mistakes.

### 4. CoLA acceptability experiment — rejected

I tested sentence-level grammatical-acceptability features from a model trained on CoLA. The result became slightly worse: RMSE 0.64959 versus 0.64538 for the existing blend.

My interpretation is that conversational fragments and Whisper punctuation do not look like the written sentences used in acceptability benchmarks. I removed this branch from the final execution path instead of keeping unsupported complexity.

### 5. Supervised DeBERTa

I fine-tuned `microsoft/deberta-v3-base` as a five-fold FP32 regression model with gradient accumulation and checkpointing. DeBERTa was weaker on its own (RMSE 0.75863), but its error correlation with the frozen and sparse models was lower. A small weight therefore improved the ensemble.

The DeBERTa/text blend reached RMSE 0.62741 before calibration. I then repeated weight selection in an outer-fold check and fitted affine calibration only on the other folds. Cross-fitted calibration and clipping produced RMSE 0.62408 and Pearson 0.78805.

### 6. Frozen WavLM — largest final gain

Text models cannot recover everything Whisper discards. I split each recording into 15-second chunks, extracted frozen `microsoft/wavlm-base-plus` hidden states, mean-pooled each chunk, and combined chunks with duration weighting. An RBF-SVR on these 768-dimensional embeddings reached RMSE 0.57904 and Pearson 0.82152 on its own.

The WavLM errors were complementary to the transcript ensemble. A nested blend-weight check selected approximately 57.5% audio and 42.5% text, producing the final OOF RMSE 0.532446 and Pearson 0.851207.

## Validation design

All headline numbers are predictions for rows that were not used to fit that fold's model:

- 5-fold shuffled stratification with fixed seed 42;
- consistent folds across model families so prediction errors are comparable;
- text vectorizers and numeric scalers fitted inside each fold;
- blend weights selected from OOF component predictions;
- affine calibration cross-fitted for reported validation results;
- a nested outer-fold check for the final audio/text weight;
- a conservative filename-group stress test for possible speaker/source leakage.

The grouped WavLM stress test was weaker than random CV (RMSE 0.60454, Pearson 0.80371), but it still retained useful signal. I therefore report the stronger random/nested OOF result with this limitation clearly stated rather than treating it as guaranteed leaderboard performance.

The selection proxy used during the final blend sweep was:

```text
0.5 × (RMSE + 1 − Pearson)
```

It gives equal selection pressure to the two competition metrics. RMSE and Pearson are still reported separately.

## Final pipeline

```text
Audio ──► WavLM ──► RBF-SVR ───────────────────────────────┐
                                                           ├─► affine calibration ─► clip [1, 5]
Audio ──► Whisper ─┬─► TF-IDF + numeric Ridge ─────────────┤
                   ├─► MPNet + numeric RBF-SVR ─► text mix ┤
                   └─► DeBERTa 5-fold regressor ───────────┘
```

The final equations are:

```text
text = 0.30 × DeBERTa + 0.42 × MPNet/numeric + 0.28 × TF-IDF
raw  = 0.575 × WavLM + 0.425 × text
pred = clip(1.18348009 × raw − 0.64239718, 1, 5)
```

The coefficients and calibration parameters were derived from training OOF predictions. They were not tuned on test labels.

## What failed and what I learned

- **Raw acoustic statistics were misleading.** They mostly detected a distinct zero-label recording batch. Auditing the source structure before trusting CV prevented a shortcut from becoming the final model.
- **CoLA features did not transfer.** Written grammatical acceptability was not a reliable proxy for spontaneous transcribed speech.
- **A zero-regime detector did not generalize to the test distribution.** Despite near-perfect OOF separation of the known batch, almost no test clips resembled it. I did not force special-case predictions into the final submission.
- **A single deep text model was not enough.** DeBERTa underperformed the simpler transcript models alone; its value came from complementary errors, so it received only a small ensemble weight.
- **Audio/text diversity mattered more than additional text complexity.** WavLM produced the largest improvement because it restored an information channel unavailable to transcript models.

## Reproducing the run

The easiest and intended environment is Kaggle:

1. Open `grammar_scoring_engine.ipynb` as a Kaggle notebook.
2. Attach the `shl-hiring-assessment-2026` competition data.
3. Enable a GPU accelerator (the recorded run used a Tesla T4).
4. Choose **Save & Run All**.
5. Download `/kaggle/working/submission.csv`.

The notebook validates the dataset contract at the start and validates the final file at the end. Expensive intermediate files are cached under `/kaggle/working`; rerunning a saved Kaggle version can reuse them.

For local inspection, Python dependencies are listed in `requirements.txt`. The notebook still expects Kaggle's competition directory layout and a CUDA-capable environment; the competition data is not redistributed here.

## Limitations and next experiments

- Only 732 rubric-valid examples are available, so blend selection still has uncertainty.
- Whisper may normalize ungrammatical speech or make transcription errors.
- The group stress test suggests that repeated speakers or recording sources could make random CV optimistic.
- The decision to exclude score `0` is supported by the audit but assumes the hidden evaluation follows the stated 1–5 rubric.
- A stronger next iteration would use speaker-aware folds if speaker IDs become available, compare multiple ASR decoders, and learn calibrated uncertainty from fold disagreement.
